# word-gloss

Last change: 2026/05/05-17:41:20.

この repository は、古典日本語テキストを word-gloss, 逐語訳, 自然訳, notes の複数層で記述するための方針と規則を管理するものです。

主な対象は、『伊勢物語』『土佐日記』などの古典日本語テキストです。各テキストは、以下の層に分けて扱います。

- word-gloss
- 逐語訳
- 自然訳
- notes

## 基本方針

本 repository の基本方針は、原文に現れている信号の連鎖をできるだけ保持することです。

word-gloss は、原文の語順、語形、形態、機能を記録するための層であり、文脈から構成される解釈を先取りして入れません。

逐語訳では、原文の時間順と句の連鎖を保持します。  
自然訳では、読みやすさのために統合を行いますが、原文にない情報を過度に補わず、読者が意味を立ち上げる余地を残します。

## 三層構造

本プロジェクトでは、翻訳と注釈を次の三層に分けます。

1. word-gloss  
   語対応、形態、機能、語順を保持する層です。

2. 逐語訳  
   原文の時間順と発話単位の連鎖を保持する訳です。完成文として整えすぎず、原文が順に立ち上がる過程を残します。

3. 自然訳  
   読みやすい完成文として提示する訳です。ただし、テキスト外の情報を過度に補わず、原文の配置や余白をできるだけ残します。

## 逐語訳を崩すトリガー

逐語訳は、説明を加えた瞬間に崩れます。

典型的なトリガーは次の通りです。

- 語彙の近似：`梅壺 -> plum jar`
- 文の統合：`ぬれて -> while`
- 主語の導入：`見て -> watched`
- 文脈補完：後続を先取りして `sang` を入れる

本 repository では、これらの操作を避け、観察可能な信号の連鎖を保持することを重視します。

## gloss-policy.md と gloss-policy.json

`gloss-policy.md` は、人間が読むための方針書です。  
判断の背景、例、例外、運用上の注意を記述します。

`gloss-policy.json` は、機械処理や検証に使うための形式です。  
将来的には `glosslint` や `jq` などの処理で利用することを想定しています。

## notes

`notes/` には、個別の判断や方法論的なメモを置きます。

例：

- 「なむ」を固定的な願望表現とせず、EMPH とする理由
- 「ものを」を常に詠嘆表現としない理由
- 「てふ」を分解する場合の扱い
- 説明を加えることで逐語訳が崩れる例
- 読者の解釈余地を閉じない翻訳

## rules

`rules/` には、将来的に検証可能な規則を置きます。

例：

- 使用可能な略号
- 必須フィールド
- lemma と word の関係
- gloss の形式
- `ku` の使い方
- 和歌と地の文の区別

## 基本的な姿勢

本 repository では、翻訳を「意味を説明する作業」としてだけでなく、原文の信号が時間の中で立ち上がる過程を記述する作業として扱います。

そのため、word-gloss と逐語訳では、原文の語順と時間順をできるだけ保持します。
自然訳では読みやすさを確保しますが、読者が文脈から構成すべき解釈を、訳文の中で先に閉じないことを重視します。
